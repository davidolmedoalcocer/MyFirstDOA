Implementé el envío centralizado de **`X-Correlation-ID`** en CSAR UI. El nuevo `CorrelationIdHeaderHandler.cs` se ejecuta después de `UserNameHeaderHandler.cs`, sin modificarlo. Lo conecté en `Program.cs`, de modo que no fue necesario editar cada método del proveedor.

El valor combina **el usuario, si está disponible, el método HTTP y la ruta**. Añade un ID numérico solo cuando la ruta o un parámetro conocido permite identificarlo. Por ejemplo:

```text
X-Correlation-ID: jdoe_GET_/CsarTasks/GetCsarTaskByID_CsarTaskId=17
```

No incluye timestamps, el cuerpo de la solicitud ni la consulta completa. Tampoco reutiliza el `CorrelationID` de Serilog ni `X-Trace-ID`.

**Pendiente:** para incluir `CsarTaskId` y `TranTaskId` juntos cuando solo se conocen en el componente, ese contexto tendrá que pasarse explícitamente a la solicitud. El handler no etiqueta un `TaskId` genérico como `TranTaskId` sin certeza.

**Validación:** CSAR UI compiló y pasaron las **169 pruebas del proveedor**. Las pruebas verifican ambos encabezados en GET, POST y PUT, y que se envía la correlación aunque no haya usuario. No modifiqué la API ni la base de datos, y no hice commit ni push.
