Integré el encabezado `UserName` en CSAR API, en la rama `features/csar-request-headers`. **Cuando el encabezado trae un valor, se usa para registrar quién realizó la acción. Si falta, está vacío o solo contiene espacios, se conserva el valor que la API usaba antes.**

| Archivo y método | Antes | Ahora |
|---|---|---|
| `BaseController.cs` — `GetAuditUserName` | Solo extraía el encabezado. | Reutiliza el lector existente y devuelve el valor anterior si no hay un `UserName` utilizable. |
| `TaskController.cs` — `UpdateCall` | Usaba `request.UserName` para la nota y el operador del historial. | Usa el encabezado para ambos registros, con `request.UserName` como respaldo. |
| `TaskController.cs` y `CsarRequestService.cs` — `UpdateTaskStatus` / `UpdateTaskStatusAsync` | Guardaban `request.UserName` como operador del historial. | El controlador pasa al servicio el usuario de auditoría por separado, sin modificar el cuerpo de la solicitud. |
| `TaskNoteController.cs` — `InsertTaskNote` | Guardaba el `UserName` de la nota recibida. | Da prioridad al encabezado para registrar al autor de la nota. |
| `ActionRequestController.cs` y `CsarRequestService.cs` — `Post` / `CreateCSARRequestAsync` | Usaban `RequestedBy` para registrar al operador que creó el CSAR y al autor de las notas locales. | Usan el encabezado para esos campos de auditoría. `RequestedBy` no se sobrescribe y sigue siendo el respaldo. |
