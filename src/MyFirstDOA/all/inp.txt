### 1. Qué hace el `BaseController` de Charles

En su `BaseController.cs`:

| Método | Qué hace |
|---|---|
| `BaseController()` | Inicializa `_loginId` y `_correlationId` como cadenas vacías. |
| `AcquireHeaderParams` | Lee `Authorization`, separa su contenido por `\|` y lanza `BadHttpRequestException` si falta o está vacío. No valida el token ni interviene en la lectura de `UserName`. |

| `ExtractCorrelationIdFromHeader` | Lee `CorrelationID` y genera un GUID si falta o está vacío. Es independiente de `UserName`; tu API actual usa `X-Correlation-ID`. |
| `AcquireHeaderValue` | Helper privado que busca el encabezado en `Request.Headers` y devuelve su valor como texto, o una cadena vacía si no existe. |

Este es el fragmento real que recibe `UserName`:

```csharp
protected void ExtractUserLoginIdFromHeader()
{
    _loginId = string.Empty;
    AcquireHeaderValue("UserName", out _loginId);

    if (string.IsNullOrEmpty(_loginId))
    {
        throw new ArgumentException("No UserName header provided");
    }
}
```

**Dependencias:** usa `ControllerBase` de ASP.NET Core MVC, `HttpRequest` y `StringValues` de `Microsoft.Extensions.Primitives`. Necesita el contexto HTTP que ASP.NET Core proporciona al ejecutar la acción. No requiere servicios adicionales en DI, acceso a base de datos ni llamar primero a `AcquireHeaderParams`. Leer el encabezado tampoco autentica al usuario.
