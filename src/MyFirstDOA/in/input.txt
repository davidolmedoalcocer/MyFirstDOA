When a Product is selected, the system shall load and display all active and deprecated Product Versions associated with that Product. Removed Product Versions shall not be displayed.

Users shall be able to create Product Versions either from scratch or by using an existing Product Version as a template. Product Versions created from an existing version shall inherit the selected version's Arguments, Configurations, and Secrets.

Each Product Version follows the lifecycle:

In Development → Released → Deprecated

New Product Versions are always created with the status In Development.

Users shall be able to edit Product Versions while they remain in the In Development state. Once a Product Version is released, its definition becomes immutable and can no longer be modified.

Users shall also be able to progress Product Versions through their lifecycle by releasing and deprecating them according to the defined business rules.

Build, Configuration, and Secret management functionality are outside the scope of this PBI, except where required to support Product Version lifecycle validation.

Business Rules
Product Versions belong to a Product.
Removed Product Versions shall not be displayed in the Version list.
Deprecated Product Versions shall remain visible in the Version list.
Product Versions shall be displayed in alphabetical order.
When Product Versions are loaded, the first Version in the sorted list shall be automatically selected.
Product Version names must be unique within a Product.
New Product Versions shall always be created with the status In Development.
Product Versions created using the From Version action shall copy:
Arguments
Configurations
Secrets
Product Versions in the Released state cannot be modified.
Product Versions in the Deprecated state cannot be modified.
A Product Version can only be released when at least one Build is associated with the Version.
Releasing a Product Version requires selecting the Build that will be associated with the release.
Product Version lifecycle transitions are irreversible.
Product Version removal requires confirmation.
Release requires confirmation.
Deprecation requires confirmation.
