Proposed changes:

Assign, don't define. The table shows the Configurations assigned to the Product Version. Remove means unassign; the Setting stays in the catalog.
Assignment drawer. It has a searchable dropdown of Configurations not yet assigned to the version, with a + next to it. + opens the existing Add Setting drawer with Configuration preselected; on save, the user returns to the assignment drawer with the new Configuration selected. Edit opens the existing Edit Setting drawer. Only one drawer is ever open (no stacking), and users never have to leave Product Management.
Edits are global. Editing a Configuration creates a new revision that every Product Version and Template using it picks up on its next deployment. The drawer already warns about this, but I think the AC should say it explicitly.
Release lock applies to assignments. On Released/Deprecated versions, hide Assign, Unassign and Edit. The definition can still change from other versions or the Settings page.
Value fields match the drawer. Value Strategy is Expression or Generated (Base64/Hex, 16/32), and the table's Value column follows the Settings page's "Resolution" preview.
Case-insensitive Keys are a good callout. Today Keys are case-sensitive, so this would be a new backend requirement and not just UI validation.
Mockups. The existing images already show the dropdown + + pattern, so I think the text here can carry the remaining drawer differences (the Setting fields follow the existing Add/Edit Setting drawer).
For context, the plan is for Product Registration to eventually carry Setting requirements with each version, so long-term this screen becomes the review/correction path. I don't think that changes the scope here, though.

Thoughts?
