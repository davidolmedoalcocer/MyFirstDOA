  La prueba se detiene ahí, con este error:

  POST /admin/OData/ProductVersionSettings

  Por eso no llega a la última comprobación (volver a consultar la versión). La versión terminó con las dos asignaciones.
  
  Por qué ocurre
  
  La única validación de duplicados en la asignación es el par (versión, SettingId). Como Region y region son dos Settings con ID distinto,
  la API las trata como claves distintas. Este es el requerimiento pendiente "Keys case-insensitive" del reporte. Es una regla del PBI, así
  que el fallo es el comportamiento correcto de la prueba mientras eso no se implemente.
