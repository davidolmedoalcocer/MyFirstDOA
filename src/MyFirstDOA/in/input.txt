  2. API: reglas de negocio y permisos
  
  Archivo: e2e/api/tests/DeploymentRequestOwnership.test.ts Prueba: [476602] second user targeting the same tenant is refused with 409 OWNERSHIP_CONFLICT
  
  - Desde dónde empieza:
    - El fixture api de e2e/api/fixtures/ApiRequestFixture.ts.
    - En el beforeEach, el fixture createTenant crea un tenant nuevo por la API. Luego se borra el draft que se abre automáticamente y se registra el borrado del tenant
  en cleanup.
  
  - Qué recorre:
    1. ApiClient (e2e/shared/client/ApiClient.ts) arma la URL con buildApiBaseUrl (http://dev-portal-service-testing:8080/customer/...). Con as: ALICE o as: BOB envía el
  header X-UserSessionModel de ese usuario (e2e/shared/Sessions.ts).
    2. El servicio .NET real recibe la petición y pasa por el filtro de prefijo de ruta /customer y por el controlador OData DeploymentRequestsController.
    3. El controlador llama a DeploymentRequestOwnershipService. Allí EnsureOwnedBy lanza OwnershipConflictException si quien llama no es el dueño.
    4. El repositorio lee y escribe en Postgres real.
  
  - Qué comprueba:
    - Alice crea el draft.
    - Bob intenta lo mismo y recibe un 409. El cliente verifica ese estado con expectedStatus: 409.
    - El cuerpo de la respuesta trae error = 'OWNERSHIP_CONFLICT', ownerId = el id de Alice, ownerName = 'alice', requestStatus = 'Draft' y un createdAt.
  
  - Backend real o simulado: real. Lo único sustituido es la identidad, que normalmente llega por Kong y aquí la pone el test en un header.

  - devPortalService/test/Api.Test/Controllers/OData/DeploymentRequestsOwnershipTests.cs, para el controlador.
