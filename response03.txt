### 1. Implementación completa de `LogAuditEventToDb`

**Hay dos capas:**

**Capa 1 — wrapper privado en SSOService** SSOService.cs:

```csharp
private async Task<bool> LogAuditEventToDb(string msgType, string msgText, string loginName, long appID)
{
    try
    {
        StackTrace stackTrace = new();
        StackFrame stackFrame = stackTrace.GetFrame(1);
        System.Reflection.MethodBase methodBase = stackFrame.GetMethod();
        return await _ssoRepo.LogAuditEventToDb(
            Guid.NewGuid().ToString(),   // msgGUID — generado en runtime
            methodBase.Name,             // sender — nombre del método llamante vía reflection
            msgType, msgText, loginName, appID,
            false);                      // saveForReplay — siempre hardcoded false
    }
    catch (Exception)
    {
        return false;                    // cualquier excepción queda silenciada
    }
}
```

**Capa 2 — repositorio** SSOAuthRepository.cs:

```csharp
public async Task<bool> LogAuditEventToDb(
    string msgGUID, string sender, string msgType, string msgText,
    string loginName, long appID, bool saveForReplay)
{
    using SqlConnection db = new(_connectionString);
    db.Open();
    DynamicParameters dapperParams = new();
    dapperParams.Add("@MessageGUID",   msgGUID);
    dapperParams.Add("@Sender",        sender);
    dapperParams.Add("@MessageType",   msgType);
    dapperParams.Add("@MessageText",   msgText);
    dapperParams.Add("@LoginName",     loginName);
    dapperParams.Add("@StoreInReplay", saveForReplay);
    dapperParams.Add("@AppID",         appID);
    dapperParams.Add("@FoundInReplay", dbType: DbType.Int32,
                     direction: ParameterDirection.Output);
    var result = await db.ExecuteAsync("SSOInsertLogEvent", ...);
    return !Convert.ToBoolean(dapperParams.Get<int>("@FoundInReplay"));
    // excepción → return false (silenciada)
}
```

### 6. Qué recibe TrackGuard para este flujo y exactamente qué campos

TrackGuard recibe **dos tipos de llamadas** para el flujo LDAP-failure:

**Tipo A — `EventLoggerInterface.LogEventInfo`** (SSOService.cs L215 y L336):  
Recibe: `InfoTypeCodeEnum.INFO` + un `string` de mensaje.  
La signatura del método `LogEventInfo(InfoTypeCodeEnum, string)` es la usada en la solución — el segundo parámetro es un string plano concatenado, no un modelo estructurado.  
La implementación de `EventLoggerInterface` está en la librería externa `DS.TrackGuard.Logging` y **no está disponible en este repositorio**.

**Tipo B — `ILoggingService.LogRequestResponse`** (middleware, LoggingService.cs L43):  
Recibe los campos del `CommRecordModel` descritos en la tabla anterior.  
Internamente llama a `_logger.LogEventComm(logModel)` — el objeto completo se pasa al `EventLoggerInterface`.

## HECHOS CONFIRMADOS

1. `LogAuditEventToDb` en SSOService es un wrapper privado que obtiene el nombre del método llamante via `StackTrace.GetFrame(1)` y lo pasa como `@Sender` al stored procedure `SSOInsertLogEvent` en SQL Server.
2. El SP `SSOInsertLogEvent` recibe 7 parámetros: `@MessageGUID`, `@Sender`, `@MessageType`, `@MessageText`, `@LoginName`, `@StoreInReplay`, `@AppID`. `@StoreInReplay` es siempre `false`.
3. El stored procedure devuelve `@FoundInReplay`; el código solo usa ese valor para el return bool del método, no para ninguna lógica de diagnóstico.
4. Si `LogAuditEventToDb` lanza excepción, esta queda silenciada (`return false`) sin registro adicional.
5. `ADWrapper._logger` es `ILogger<ADWrapper>` (Serilog), no `EventLoggerInterface` (TrackGuard).
6. `SSOService._logger` es `EventLoggerInterface` (TrackGuard). `SSOService._log` es `ILogger<SSOService>` (Serilog).
7. El `LogError` de ADWrapper L190 va a Serilog; Serilog está configurado con `.Enrich.WithCorrelationIdHeader("CorrelationID")`, por lo que `CorrelationID` se añade automáticamente a ese log.
8. El TrackGuard `EventLoggerInterface` se inicializa con `EventLoggerFactory.CreateLogger_WebServiceType(true, ApplicationName, MachineName, CommonLoggingAPI_URL)` — recibe una URL de API externa.
9. `RequestResponseLogging` middleware nula los campos `Password`, `NewPassword`, `OldPassword` del body antes de loguearlo, pero **no nula `LoginName`**.
10. El `CorrelationID` llega al `RequestResponseLogging` middleware vía `IRequestHeaderAccessor`, que lo lee del header HTTP.
11. El middleware `RequiredHeaderValidatorMiddleware` genera un nuevo GUID como `CorrelationID` si el request no trae uno en el header.
