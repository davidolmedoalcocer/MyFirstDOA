### 11. Qué puede distinguir el código realmente

#### Para usuarios AD (ruta LDAP — el flujo del incidente):

| Condición | Código devuelto | Mecanismo |
|---|---|---|
| Login no existe en SSO DB (`GetUserAsync` = null) | `LOGIN_DOES_NOT_EXIST` | SSOService.cs — antes de llamar a LDAP |
| LDAP bind falla + usuario **no existe** en Graph API | `LOGIN_DOES_NOT_EXIST` | ADWrapper.cs — `GetUserDetail` devuelve null |
| LDAP bind falla + usuario **sí existe** en Graph API | `PASSWORD_INVALID_CREDENTIALS` | ADWrapper.cs — `GetUserDetail` devuelve el user |
| LDAP bind tiene éxito + `AccountEnabled == false` en Graph | `LOGIN_INACTIVE` | ADWrapper.cs |
| Host inaccesible / error SSL | `UNEXPECTED_EXCEPTION` | SSOService.cs — catch genérico |

#### Lo que el código **no puede distinguir** dentro de un LDAP bind fallido:

El `catch (LdapException ex)` [ADWrapper.cs L189] **no inspecciona `ex.ResultCode`**. Por tanto, a nivel de log, son indistinguibles:
- Contraseña incorrecta (LDAP code 49)
- Cuenta bloqueada en AD (LDAP code 49 con subcode, dependiendo del DC)
- Contraseña expirada en AD (LDAP code 49 con subcode)

Todos generan exactamente el mismo log `ValidateCredentials failed: {Message}|{InnerException}` y el mismo código de retorno `PASSWORD_INVALID_CREDENTIALS`.

## HECHOS CONFIRMADOS

1. `ValidateCredentials` se llama **dos veces** para un único `POST /Authentication/Login` no-BAL: primera vez con NGLS, segunda si la primera devuelve `false` — SSOService.cs.
2. La condición para la segunda llamada es exclusivamente `if (!success)` [L340]. No se evalúa la causa del fallo.
3. Ambas llamadas usan los mismos `login` y `password` del request original, sin modificación entre ellas.
4. El `username` enviado al LDAP bind tiene el formato `domain\login` si `domain` es no vacío [ADWrapper.cs L175].
5. El puerto LDAP es siempre 636 (`DEFAULT_SSL_PORT`) [ADWrapper.cs L183].
6. Solo se captura `LdapException` dentro de `ValidateCredentials` [ADWrapper.cs L189]. Otros errores (red, SSL) no generan ese log.
7. La respuesta al cliente cuando ambos fallan es `HTTP 400 PW018` [AuthenticationController.cs L38].
8. El código no lee `LdapException.ResultCode` — no distingue contraseña incorrecta, cuenta bloqueada o contraseña expirada dentro del bind.
9. Los hostnames de los servidores LDAP no están en el repositorio — provienen de ProcessMonitor clave `AppSettings_NglsHostName` y `AppSettings_NgicHostName`.
10. La ruta LDAP solo se activa si `GetUserPrefsAsync(InternalAccountPrefix + login)` devuelve vacío (usuario no-BAL) y `GetUserAsync(login)` devuelve no-null.
