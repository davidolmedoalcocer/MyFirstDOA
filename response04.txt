## HECHOS CONFIRMADOS

**Traza completa del flujo de credenciales:**

**1. Punto de entrada — formulario HTML**
LoginScreen.razor: El usuario teclea manualmente `UserName` y `Password` en un `<form method="post" action="/login">`. No hay pre-relleno, no hay valores por defecto.

**2. Endpoint receptor**
Program.cs, `app.MapPost("/login", ...)`: Lee `context.Request.Form["UserName"]` y `context.Request.Form["Password"]` y los mete en un objeto `LoginCredentials`.

**3. Handler de autenticación**
LoginLogoutHandler.cs, método `LoginUserAsync`: llama directamente a:
```
_authService.Authenticate(credentials.Username, credentials.Password, 117)
```
El `117` es el `ApplicationId`, hardcodeado.

**4. Llamada HTTP a SSOApi**
SSOService.cs, método `Authenticate`: construye el modelo:
```
authModel.LoginName = userName;   // viene del formulario
authModel.Password  = password;   // viene del formulario
authModel.ApplicationId = [117];
```
Serializa a JSON y ejecuta `POST Authentication/Login`.

## ORIGEN DE LAS CREDENCIALES

**Opción 1 — Usuario final: CONFIRMADO.**

`LoginName` y `Password` los introduce el usuario final en el formulario web. No existe ningún mecanismo de service account, HashiCorp Vault, Kubernetes Secret, variable de entorno ni configuración para las credenciales de autenticación de usuario.

Lo único que sí pasa por `EnvironmentDetector` (servicio externo en `https://env-detector-api.appsprod.ngls.ngic.com/api/Environment/`) es la **URL del endpoint de SSOApi**, no las credenciales. La clave usada es `"SSOAPI"` ([appsettings.Production.json, sección `Authenticate`](DS.UI.Web.DocExtractVerify/DS.UI.Web.DocExtractVerify.UI/appsettings.Production.json#L52-L56)).

**Modelo que se envía a SSO:**
Clase `Authentication` (Models.cs) que mapea 1:1 con `AuthenticationModel` de SSOApi (SSOApi/Models/AuthenticationModel.cs/SSOApi/Models/AuthenticationModel.cs#L4-L9)): `LoginName`, `Password`, `ApplicationId`, `IpAddress`.

**¿La contraseña se cachea o reutiliza?**
No. LoginLogoutHandler.cs: `_memoryCache.Set(...)` guarda únicamente el `sessionId` (GUID) con TTL de 5 minutos, nunca la contraseña. No existe ningún mecanismo que preserve o reutilice una contraseña anterior/stale.
