# Análisis de impacto — SSO Admin y Client Source Admin

## CONTEXTO

Acabo de realizar una demo de una corrección relacionada con el campo `LastNameFirst`, utilizado para mostrar correctamente el nombre del usuario en el mensaje de bienvenida de Track Guard, evitando que aparezca `Welcome undefined`.

La corrección realizada consiste en asegurar que `LastNameFirst` se envíe correctamente durante la creación y actualización de usuarios, antes de ejecutar el procedimiento almacenado correspondiente.

Durante una revisión, mi jefa Jayati expresó una preocupación importante:

**Necesitamos confirmar que esta modificación no afecte el funcionamiento de Client Source Admin, especialmente si SSO Admin y Client Source Admin comparten endpoints, controladores, métodos, servicios o procedimientos almacenados.**

Jayati también explicó que existen dos tipos de usuarios:

- **Usuarios internos:** se autentican mediante Active Directory y utilizan identificadores IID.
- **Usuarios externos (Client Source):** no pertenecen al Active Directory interno y utilizan otro mecanismo de autenticación y administración.

Los flujos de ambos tipos de usuarios deben conservar su comportamiento actual.
