## Contexto histórico confirmado

Repositorio: `/workspaces/dev-portal`

Rama de trabajo: `fix/dev-portal-setup-improvements`

Error original: la tarea `Dev: Start UI` fallaba con `EACCES` cuando `pnpm install` intentaba modificar:

- `sharedUIComponents/node_modules/.bin`
- `adminUi/node_modules/@tsconfig/node22`

Existían archivos `root:root` mientras que el usuario del Dev Container era `node`, UID 1000.

En la investigación inicial se repararon los permisos usando `chown`. Eso permitió iniciar las aplicaciones, pero no identificó el proceso histórico que creó dichos archivos como root.

## Cambios que ya existen en la rama

**1. `docker-compose-devui.yml`**

Admin UI y Tenant UI utilizan:

`user: "${DEV_UID}:${DEV_GID}"`

Originalmente esos servicios no tenían `user:` y podían ejecutar procesos como root.

**2. `.devcontainer/detect-and-write-volume.sh`**

Agregamos:

```bash
DEV_UID="$(id -u)"
DEV_GID="$(id -g)"

printf 'DEV_UID=%s\nDEV_GID=%s\n' "$DEV_UID" "$DEV_GID" >> "$ENV_FILE"

echo "Wrote DEV_UID=$DEV_UID DEV_GID=$DEV_GID to $ENV_FILE" >> "$LOG"
```

El script regenera `.env` desde `.env.template` y se invoca mediante `postCreateCommand.sh` y `postStartCommand.sh`.

**3. `.env` local**

Se agregaron manualmente `DEV_UID=1000` y `DEV_GID=1000` para comprobar la configuración actual. Esta intervención manual NO debe ser requisito para otros desarrolladores.

## Pruebas ya realizadas

- Sintaxis Bash válida.
- Docker Compose acepta la configuración.
- Compose resuelve ambos servicios como UID/GID 1000.
- Ambos contenedores reportaron `uid=1000(node) gid=1000(node)`.
- `Dev: Start UI` se ejecutó sin reportar EACCES.
- Los tres `node_modules` examinados tenían cero entradas con UID 0.
- Las interfaces funcionaron con el backend disponible.

**Problemas pendientes conocidos:**

- No está identificado el proceso histórico que creó los archivos afectados como root.
- Vite puede escribir en `.vite`, pero eso no demuestra que creara `.bin` o `@tsconfig/node22`.
- Las variables sin definir pueden provocar una configuración Compose inválida.
- La generación automática del `.env` modificado todavía no se ha demostrado mediante un nuevo inicio.
- El caso de UID diferente de 1000 no se ha probado dinámicamente.
- Las URLs y los puertos incorrectos corresponden a otro hallazgo y están fuera de alcance.
