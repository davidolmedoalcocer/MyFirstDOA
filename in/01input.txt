### Contexto confirmado

Rama: fix/dev-portal-setup-improvements.

Error histórico:
- Dev: Start UI fallaba con EACCES en sharedUIComponents/node_modules/.bin y adminUi/node_modules/@tsconfig/node22.
- Había archivos root:root.
- El Dev Container trabajaba como node, UID 1000.
- Se recuperó temporalmente mediante chown.

Corrección actual:
1. .devcontainer/detect-and-write-volume.sh obtiene id -u e id -g y los escribe como DEV_UID y DEV_GID en .env.
2. docker-compose-devui.yml utiliza user: "${DEV_UID}:${DEV_GID}" en Admin UI y Tenant UI.
3. postCreateCommand.sh y postStartCommand.sh ejecutan el script de detección.

Pruebas ya realizadas:
- Bash y Docker Compose aceptan la configuración.
- Compose resuelve ambos usuarios como 1000:1000.
- docker exec id devolvió uid=1000(node), gid=1000(node) en ambos contenedores.
- Dev: Start UI inició sin EACCES reportado.
- find -uid 0 devolvió cero entradas en los tres node_modules.
